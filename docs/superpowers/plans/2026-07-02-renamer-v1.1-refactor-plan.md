# Renamer v1.1 重构与优化实施计划

> **For agentic workers:** 按任务顺序逐项实施，使用复选框（`- [ ]`）跟踪进度。每个 Phase 可独立合并发布；Phase 内任务按序执行。
>
> 本计划基于 2026-07-02 对 v1.0.0（commit `119d268`）的整体审查，取代 `2026-06-27-renamer-redesign-plan.md`（该计划已全部落地）。

**目标：** 在不破坏 v1.0.0 已有行为的前提下，先做内部重构消除结构性债务，再补齐安全短板（API Key 明文）与设计文档中承诺但未实现的核心体验（进度/取消、回滚入口、目标目录选择），最后完成若干增强项。

**技术栈不变：** Swift 6、SwiftUI、SPM、macOS 14+、`StrictConcurrency`、XCTest。遵循 AGENTS.md 全部既有约定（中文注释、`LocalizedError` + `errorDescription`、actor 隔离可变状态、业务逻辑不进 View）。

## 审查结论摘要（计划依据）

### 与原设计文档的差距

| 设计文档承诺 | 现状 |
|---|---|
| §7 大目录显示进度条、分析/执行可取消 | 只有 `isAnalyzing` 布尔值，无进度、无取消入口 |
| §5.9 / §2 操作记录支持一键回滚 | `RollbackService.rollback` 已实现但无任何 UI 入口，也无法列出历史记录 |
| §6.4 预览顶部统计（本地分析数、云端增强数、冲突数） | 只显示操作总数 |
| §6.1 菜单栏弹窗含最近任务列表、设置入口 | 弹窗只有「整理/打开主窗口/退出」 |
| §6.5 设置含「导出：DEVONthink 数据库/组选择」 | DEVONthink 配置只能逐任务填写 |
| §8 重复文件保留策略「全部保留/保留最新」 | 只有逐组手选保留项 |
| §3.3 Vision OCR | 未实现（图片仅读 EXIF 元数据） |
| 安全备注：API Key 迁移 Keychain | 仍明文存于 `settings.json` |

### 代码结构问题（重构点）

1. **`MainViewModel.analyze` 是 135 行的上帝方法**（`MainViewModel.swift:26-161`）：扫描、本地分析并发、云端限速批处理、去重、建计划、消息拼装全部内联。无法复用、无法上报进度、难以测试。
2. **云端增强用「批栅栏」限速**（`MainViewModel.swift:89-121`）：每批 3 个、整批等完才发下一批，慢请求阻塞整批（head-of-line blocking）。
3. **`LocalAnalyzer` 声明为 `actor` 但全部方法 `nonisolated`**，实际无隔离状态，应为 `struct`；`analyze(item:)` 与 `analyze(item:text:)` 两个重载有约 30 行近乎复制的函数体。
4. **`Organizer` 用异常传递非致命结果**：「目标已存在被跳过」包装成 `OrganizerError` 抛出，调用方再解包判断是否其实是成功（`MainViewModel.swift:206-215`），控制流扭曲。
5. **错误/成功提示由两个 `String?` + 手写 alert Binding 承载**，同一段 alert 代码在 `ContentView` 和 `PlanPreviewView` 重复。
6. **`MainViewModel` 用 5 个 `last*` 散装属性缓存重建计划所需参数**，应聚合为一个上下文结构。
7. **死代码**：`TaskListViewModel.templates` 无任何使用方。
8. **`CloudAnalyzer` 用 `JSONSerialization` + `[String: Any]` 手拼请求/解析响应**，应改 `Codable`。
9. **设置持久化时机散乱**：`onChange`/`onSubmit`/`onDisappear` 各处手动 `save()`，`onSubmit` 漏掉失焦未回车的编辑。
10. **无日志**：多处注释写着「可在后续版本加入日志」。

### 非目标（本计划不做）

- Vision OCR、感知哈希「疑似重复」检测（价值/成本比低，留待 v1.2 评估）。
- Shortcuts/AppleScript 系统集成（原设计已明确暂不实现）。
- 沙盒化与安全书签（改动面大，独立立项）。
- 代码签名与公证（需开发者账号，属发布流程而非代码任务；图标见 Phase 4 可选项）。
- 多语言/本地化框架。

```swift
/// 一次完整分析的输入参数（同时充当重建计划所需的上下文快照）。
struct AnalysisRequest: Sendable {
    let folders: [URL]
    let taskID: UUID?
    let template: NamingTemplate
    let destination: URL
    let operation: CopyOrMove
    let exportTargets: [ExportTarget]
    let cloudConfig: CloudConfiguration?   // nil 表示不启用云端增强
}

/// 分析各阶段的进度事件（Phase 1 先定义类型并贯通回调，UI 到 Phase 3 再接）。
enum AnalysisProgress: Sendable {
    case scanning
    case analyzing(completed: Int, total: Int)
    case enhancing(completed: Int, total: Int)
    case detectingDuplicates
    case buildingPlan
}

/// 分析结果：计划 + 各类非致命告警计数。
struct AnalysisOutcome: Sendable {
    let plan: OrganizationPlan
    let items: [FileItem]                  // 供 rebuildPlan 使用
    let inaccessibleDirectoryCount: Int
    let analysisFailureCount: Int
    let hashFailureCount: Int
    let cloudFailureCount: Int
}

/// 编排扫描 → 本地分析 → 云端增强 → 去重 → 建计划的完整流水线。
/// 无隔离状态，struct 即可；并发都发生在内部 TaskGroup 中。
struct AnalysisPipeline: Sendable {
    let scanner: FileScanner
    let localAnalyzer: LocalAnalyzer
    let duplicateDetector: DuplicateDetector

    func run(
        _ request: AnalysisRequest,
        onProgress: @escaping @Sendable (AnalysisProgress) -> Void
    ) async throws -> AnalysisOutcome
}
```

- [ ] **Step 1**：新建 `AnalysisPipeline.swift`，把 `MainViewModel.analyze` 中的扫描、本地分析 TaskGroup、云端增强、去重、`NamingEngine.buildPlan` 逻辑原样搬入 `run(_:onProgress:)`。云端限速逻辑此步先原样搬移（批处理改进在 Task 1.2）。各阶段插入 `onProgress` 回调与 `Task.checkCancellation()`（用抛 `CancellationError` 取代现在散落的 `guard !Task.isCancelled else { return }`）。
- [ ] **Step 2**：`MainViewModel` 瘦身——`analyze(...)` 只负责：组装 `AnalysisRequest`（含从 `settings` 读云端配置）、调用 pipeline、把 `AnalysisOutcome` 写入 `plan` 并拼装告警文案。删除 `lastTemplate/lastDestination/lastItems/lastExportTargets/lastOperation` 五个属性，改存 `private var lastRequest: AnalysisRequest?` 与 `private var lastItems: [FileItem]?`（由 outcome 提供），`rebuildPlan()` 改用它们。

```swift
/// 基于 Security 框架 kSecClassGenericPassword 的最小封装。
/// service 固定为 "com.renamer.credentials"，account 由调用方指定。
struct KeychainStore: Sendable {
    let service: String

    func read(account: String) throws -> String?
    func write(account: String, value: String) throws   // 存在则更新
    func delete(account: String) throws                 // 不存在不报错
}
```

- [ ] **Step 1**：实现 `KeychainStore`（`SecItemCopyMatching`/`SecItemAdd`/`SecItemUpdate`/`SecItemDelete`）。错误类型 `KeychainError: LocalizedError` 带中文 `errorDescription`。

## 风险与回退

- **最脆弱假设**：非沙盒 SPM 可执行文件（无签名）读写 Keychain generic password 无需 entitlements。若在无签名 app 上遇到 `errSecMissingEntitlement` 或每次启动弹授权，回退方案已内置——`KeychainStore` 失败不阻断其它设置，临时可退回内存态 key（不落盘），并把签名提上日程。Task 2.1 Step 4 的手动验证必须在 `.app` 包形态（`package.sh` 产物）下也执行一次。
- **回滚 = 删除复制产物**，属破坏性操作：UI 必须走 destructive 确认对话框（Task 3.2 Step 3 已列入），且逐条失败不中断其余条目（现有 `RollbackAggregateError` 语义保留）。
- 所有重构任务以 `swift test` 全绿为合并门槛；任何一步测试转红，先修再进下一步。
- 本计划不改数据格式（`FileOperationRecord`/`tasks.json` 不变；`settings.json` 仅删除 key 字段，旧版本读新文件会得到空 key——可接受，因为不支持降级携带密钥）。

## 依赖清单

- 无新第三方依赖、无新 API Key、无新外部服务。Keychain 使用系统 `Security.framework`，日志使用系统 `os` 框架。
